## What this session resolved

**The beta backend routing mystery is solved.** Real app traffic was landing on `mymigo_dev`/`api-dev.mymigo.fr` instead of the newly built `mymigo_beta`/`api-test.mymigo.fr`, despite every infrastructure layer (Caddy, DNS, TLS/SNI, port/PID binding) checking out correct. Root cause: build 11 was compiled *before* EAS's hosted `EXPO_PUBLIC_API_URL` environment variable was corrected to point at the beta backend — env vars bake into the JS bundle at build time and don't retroactively update. Confirmed by extracting build 11's `.aab` and grepping the compiled bundle directly (found `api-dev.mymigo.fr`, zero occurrences of `api-test.mymigo.fr`). Build 12 (built after the variable was fixed) has the correct value, was submitted via `eas submit --platform ios --latest`, installed on the test iPhone, and confirmed via DB row-count test to correctly write to `mymigo_beta`.

**Full list of what was fixed this session** (details in `docs/beta-deployment-lessons.md`, written this session):
1. Beta app now correctly talks to the beta backend (build 12).
2. Server idempotency fix in `children.controller.ts` — `createChildFromOnboarding` now checks `enrollment.child_device_id` before creating a new child, preventing duplicate child+friend records when the app is backgrounded mid-onboarding and the client retries. Deployed and restarted on beta.
3. Redis isolation — `mymigo-beta`'s `.env` `REDIS_URL` changed from the shared `redis://127.0.0.1:6379` (same as dev, db 0) to `redis://127.0.0.1:6379/1`, giving beta its own logical Redis database.
4. Avatars migrated from dev to beta: `mascot_avatars` table copied directly (stable text ids), `ai_friends.avatar_url` synced by matching on `name` (ids are random UUIDs, differ per DB), physical files `robocopy`'d from `public/avatars`, URLs bulk-replaced from `api-dev.mymigo.fr` to `api-test.mymigo.fr`.
5. Confirmed (via `.env` diff) that dev and beta have identical API keys — ElevenLabs/Gemini/Anthropic/fal — so the earlier "voices sound off" concern isn't a config issue. Confirmed via PM2 logs that Gemini TTS is succeeding directly on beta (no fallback to ElevenLabs).
6. Static/shared audio cache (`public/audio/*.wav` — onboarding narration, mascot bubbles, tour steps, star friend intros) needs to be present on beta before real beta families start, both for latency and to avoid exhausting Gemini TTS's 10 req/min quota during concurrent onboarding. Plan: `robocopy` the whole folder from dev (cache keys are pure text hashes, no environment-specific component, fully portable) rather than re-running the throttled `audio:pregenerate` script.
7. Recovered from two separate PM2/Windows "zombie process" hangs (one required a full VPS restart via KVM) — see lessons doc for mitigation ideas not yet applied (switch beta off `ts-node` to compiled `dist/index.js`, add `max_memory_restart` to `ecosystem.config.js`).
8. Fixed a broken local `claude` CLI install on Tim's machine (interrupted auto-update left only a `claude.exe.old.<timestamp>` file, no `claude.exe`) — restored via rename, recommended a clean reinstall.
